# 欢匠·序流排队分诊管理系统 - 项目部署架构说明

> **文档位置：** `docs/architecture/` · 组件或路由变更请同步更新本文档及 [实施与部署方案](../deployment/实施与部署方案.md)

## 当前项目结构对上线发布的影响分析

### ✅ 优势
1. **统一版本控制** - 所有组件在同一仓库，便于版本同步
2. **共享配置管理** - 数据库脚本、部署文档集中管理
3. **集成测试便利** - 可以整体联调测试

### ⚠️ 潜在问题
1. **部署耦合度高** - 前端组件无法独立构建部署
2. **团队协作冲突** - 多人同时修改不同组件时容易冲突
3. **资源管理复杂** - 需要完整环境才能开发单个组件

## 推荐的组件区分与部署策略

### 组件功能定位

| 组件目录 | 技术栈 | 说明 | 部署方式 | 访问端口/路径 |
|---------|--------|------|----------|--------------|
| **pdjh-server** | Java Spring Boot | 核心业务后端服务 | 独立 JAR 包部署 | `:8080`，Nginx 反代 `/api/` |
| **HJ官网** | 纯静态 HTML | 企业展示官网 | Nginx 静态托管 | `/`（根路径） |
| **HJ管理后台/Gocent.Manager** | Vue 3 + Element Plus + Vuex | Web 管理控制台 | Nginx 静态托管 | `/admin` |
| **HJ叫号器** | .NET 4.8 WPF | 门诊/药房/检验/体检窗口叫号 | 客户端安装包 | 桌面应用 |
| **HJ候诊区大屏** | Vue 3 + Vite + Element Plus | 候诊区 / 叫号大屏（SCREEN） | Nginx 静态托管 | `/screen` |
| **HJ诊室门边屏终端** | Vue 3 + Vite | 诊室门边竖屏（可选） | Nginx 静态托管 | `/clinic` |
| **HJ自助签到终端** | Vue 3 + Vite | 患者现场签到 | Nginx 静态托管 | `/checkin` |
| **HJ护士工作站** | Vue 3 + Vite | 分诊台护士 Web 工作台 | Nginx 静态托管 | `/nurse` |
| **HJ体检H5** | Vue 3 + Vite | 体检导诊 H5 | Nginx 静态托管 | `/checkup` |

### Nginx路由配置建议

```nginx
# 完整的Nginx配置示例
server {
    listen 80;
    server_name queue.hospital.local;

    # 1. 官方网站 (根路径)
    location / {
        root /usr/share/nginx/html/website;
        index index.html;
        try_files $uri $uri/ /index.html;
    }

    # 2. 候诊大屏系统
    location /screen {
        alias /usr/share/nginx/html/screen;
        index index.html;
        try_files $uri $uri/ /screen/index.html;
    }

    # 3. 患者签到H5
    location /checkin {
        alias /usr/share/nginx/html/checkin;
        index index.html;
        try_files $uri $uri/ /checkin/index.html;
    }

    # 3b. 分诊台护士工作站
    location /nurse {
        alias /usr/share/nginx/html/nurse;
        index index.html;
        try_files $uri $uri/ /nurse/index.html;
    }

    # 4. 体检服务 H5
    location /checkup {
        alias /usr/share/nginx/html/checkup;
        index index.html;
        try_files $uri $uri/ /checkup/index.html;
    }

    # 5. 管理后台 Web
    location /admin {
        alias /usr/share/nginx/html/admin;
        index index.html;
        try_files $uri $uri/ /admin/index.html;
    }

    # 6. HJ诊室门边屏终端（可选，目录 HJ诊室门边屏终端）
    location /clinic {
        alias /usr/share/nginx/html/clinic;
        index index.html;
        try_files $uri $uri/ /clinic/index.html;
    }

    # 7. 后端 API 代理
    location /api/ {
        proxy_pass http://backend_cluster/;
        proxy_set_header Host $host;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_read_timeout 3600s;
        proxy_send_timeout 3600s;
    }

    # 8. WebSocket 长连接支持
    location /ws {
        proxy_pass http://backend_cluster/ws;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }
}
```

### 独立构建与部署流程

#### 1. 后端服务部署
```bash
# 构建后端
cd pdjh-server
mvn clean package -DskipTests

# 部署到服务器
scp target/pdjh-server-0.0.1-SNAPSHOT.jar server:/opt/huanjiang/server/

# 启动服务
ssh server "nohup java -Xms2g -Xmx4g -jar /opt/huanjiang/server/pdjh-server-0.0.1-SNAPSHOT.jar --spring.profiles.active=prod > server.log 2>&1 &"
```

#### 2. 前端组件独立构建
```bash
# 候诊大屏 + 门边屏（推荐）
npm run build:displays

# 候诊大屏系统（Vue3 + Vite）
cd HJ候诊区大屏
npm install
npm run build
# 输出到: dist/ -> 部署到 /usr/share/nginx/html/screen

# 签到H5
cd HJ自助签到终端
npm run build
# 输出到: dist/ -> 部署到 /usr/share/nginx/html/checkin

# 护士工作站
cd HJ护士工作站
npm run build
# 输出到: dist/ -> 部署到 /usr/share/nginx/html/nurse

# 体检H5
cd HJ体检H5
npm run build
# 输出到: dist/ -> 部署到 /usr/share/nginx/html/checkup

# 管理后台 Web（若本地仍为 HJ后台/Gocent.PDJH，见 scripts/rename-HJ管理后台.ps1）
cd HJ管理后台/Gocent.Manager
npm run build
# 输出到: dist/ -> 部署到 /usr/share/nginx/html/admin

# HJ诊室门边屏终端（可选，目录 HJ诊室门边屏终端）
cd HJ诊室门边屏终端
npm run build
# 输出到: dist/ -> 部署到 /usr/share/nginx/html/clinic
```

#### 3. 官网静态部署
```bash
# 官网是纯静态文件，直接复制
cd HJ官网
# 所有文件直接复制到 /usr/share/nginx/html/website/
```

#### 4. 桌面客户端打包
```bash
# 叫号器
cd HJ叫号器
# Visual Studio 打开 Gocent.CallStation.sln 后发布安装包
```

> **说明：** **HJ管理后台**（目录 `HJ管理后台/Gocent.Manager`）通过浏览器访问 `/admin`；**HJ叫号器**（目录 `HJ叫号器`）为 WPF 桌面端，需安装包分发。

### CI/CD流水线建议

```yaml

  push:

    steps:
```

## 团队协作与版本管理

### 分支策略
- `main` - 生产环境稳定版本
- `dev` - 开发环境集成版本
- `feature/*` - 功能分支
- `hotfix/*` - 紧急修复分支

### 组件开发规范
1. **后端团队** - 专注于`pdjh-server`目录
2. **前端团队** - 按组件分工：官网、大屏、H5等
3. **桌面团队** - 负责 **HJ叫号器**（目录 `HJ叫号器`）WPF 应用开发

### 代码审查流程
1. 每个组件修改后创建独立的PR
2. 指定相关组件负责人审查
3. 通过CI测试后合并到dev分支
4. 定期从dev合并到main进行发布

## 总结

**当前项目结构适合中小型团队和项目规模**，通过合理的Nginx配置和独立构建流程，可以实现：

1. ✅ 组件功能清晰区分
2. ✅ 独立构建和部署能力
3. ✅ 统一的版本管理
4. ✅ 便于整体联调测试

**如果未来团队规模扩大或项目复杂度增加**，可以考虑迁移到Monorepo架构或完全分离的独立仓库。

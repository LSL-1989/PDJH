# 显示屏终端分层改造 — 现场升级检查清单

> **适用版本：** 候诊大屏 Vue3 迁移 + SCREEN/CLINIC 边界厘清 + 门边屏独立配置  
> **关联文档：** [显示屏终端分层说明](../architecture/显示屏终端分层说明.md)、[实施与部署方案](./实施与部署方案.md)

---

## 一、升级前准备

| # | 检查项 | 说明 |
|---|--------|------|
| 1 | 备份数据库 | 至少备份 `doc_screen`、`sys_config`、`screen_room_mapping` |
| 2 | 记录现网模板 | 各 SCREEN 设备当前 `template_route`（如 `/pdjh4`、`/GlobalHub`） |
| 3 | 区分终端类型 | 列出每台硬件：候诊大屏 / 门边屏 / 签到机，对应 Shell 类型 |
| 4 | 构建机 Node.js | **Node 18+**（推荐 20），用于 `npm run build:terminals` |
| 5 | 后端 JDK | **JDK 17**，用于重新打包 `pdjh-server` |

---

## 二、推荐升级顺序

```text
1. 停维护窗口（可选，建议低峰期）
2. 数据库迁移（CLINIC template_route 清理，可选）
3. 部署 pdjh-server 并重启
4. 部署管理后台 /admin
5. 部署 HJ候诊区大屏 /screen
6. 部署 HJ诊室门边屏终端 /clinic
7. 部署 HJ自助签到终端 /checkin（如有）
8. 逐台终端 Resolve 验收
9. 业务联调（叫号 → 大屏 → 门边屏）
```

## 三、构建与发布

### 3.1 后端

```bash
cd pdjh-server
mvn clean package -DskipTests
# 部署 jar 并重启
```

重启后确认菜单出现：**门边屏显示配置**（`SysMenuSeedRunner` 补种）。

### 3.2 前端（仓库根目录）

```powershell
npm run build:terminals
# 或
.\scripts\build-terminals.ps1
```

| 产物目录 | Nginx 路径 |
|----------|------------|
| `HJ候诊区大屏/dist` | `/screen` |
| `HJ诊室门边屏终端/dist` | `/clinic` |
| `HJ自助签到终端/dist` | `/checkin` |

### 3.3 Nginx 关键 location（勿漏 `/clinic`）

```nginx
location /screen/ {
    alias /usr/share/nginx/html/screen/;
    try_files $uri $uri/ /screen/index.html;
}
location /clinic/ {
    alias /usr/share/nginx/html/clinic/;
    try_files $uri $uri/ /clinic/index.html;
}
location /checkin/ {
    alias /usr/share/nginx/html/checkin/;
    try_files $uri $uri/ /checkin/index.html;
}
location /api/ {
    proxy_pass http://127.0.0.1:8081/api/;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
}
```

## 五、后台配置验收

### 5.1 屏幕管理（`/deviceManage/ScreenManages`）

| 终端类型 | 配置要求 |
|----------|----------|
| **SCREEN** | 绑定诊区/多诊室；设置 **候诊模板路由**；启用 |
| **CLINIC** | **不显示**模板路由；**仅绑 1 个诊室**；启用 |

### 5.2 显示配置

| 菜单 | 适用 |
|------|------|
| 候诊区大屏配置 | 仅 SCREEN 设备 |
| 门边屏显示配置 | 仅 CLINIC 设备（脱敏、等候列表、轮询间隔） |

## 六、接口自测（PowerShell）

仓库根目录一键脚本（基础校验 + 可选现场设备码）：

```powershell
# 基础冒烟（连通性、参数校验、未注册 404）
npm run smoke:terminals
# 或
.\scripts\smoke-terminals.ps1 -ScreenDeviceCode "<SCREEN设备码>" -ClinicDeviceCode "<CLINIC设备码>"
```

手工抽查示例：

```powershell
$base = "http://127.0.0.1:8081/api"
Invoke-RestMethod "$base/Terminal/Resolve?deviceCode=<SCREEN设备码>&terminalType=SCREEN"
Invoke-RestMethod "$base/ClinicScreen/GetDisplay?deviceCode=<CLINIC设备码>"
```

**预期：**

- CLINIC `Resolve` → `status=READY`，`templateRoute` 空/null
- `GetDisplay` → 含 `screen.nameDesensitize`、`screen.showWaitList`
- `GetDeviceRoute` + CLINIC → HTTP 400 + 提示使用 `/clinic/`

## 七、终端 Shell 验收

| Shell | 首页 URL | 误装防护 |
|-------|----------|----------|
| SCREEN | `{base}/screen/` | CLINIC 设备 → `/wrong-terminal` |
| CLINIC | `{base}/clinic/` | SCREEN 设备 → 绑定页错误提示 |
| CHECKIN | `{base}/checkin/` | — |

**每台设备检查：**

1. 开机自动打开正确 URL
2. `Terminal/Resolve` 返回 READY
3. SCREEN 进入配置的 pdjh 模板或 GlobalHub
4. CLINIC 显示诊室医生与队列
5. 叫号器叫号后，大屏与门边屏 **≤3 秒** 刷新

## 八、Legacy 说明

- `pdjh2`、`pdjh9` 为历史门边屏模板，**新现场禁止使用**
- 已有 pdjh2/pdjh9 的老项目：计划迁移至 `HJ诊室门边屏终端`，或签书面例外

## 九、回滚方案

| 层级 | 回滚方式 |
|------|----------|
| 前端 | 恢复上一版 `dist` 备份（screen/clinic/checkin 独立回滚） |
| 后端 | 恢复上一版 jar；数据库迁移一般可保留（仅清空 CLINIC template_route） |
| 配置 | `doc_screen` 与 `sys_config` 有备份即可还原 |

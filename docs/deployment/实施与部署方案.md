# 欢匠·序流排队分诊管理系统 - 标准实施与部署方案

> **文档位置：** `docs/deployment/` · 部署方式变更请同步更新本文档及 [项目部署架构说明](../architecture/项目部署架构说明.md)

本方案旨在指导现场 IT 实施工程师、项目经理及运维团队，将“欢匠·序流排队分诊管理系统”平滑、规范且安全地部署至医疗机构的生产环境或政务云环境中。

---

## 一、 概述与系统架构清单

本平台采用 **Monorepo 前后端分离** 架构（根目录 `pnpm-workspace.yaml` 管理多前端子工程）。在实施部署前，请确认以下子系统资产清单已准备就绪：

1. **核心调度引擎 (Backend)**
   - `pdjh-server`：基于 Java Spring Boot 的核心分诊排队与调度服务引擎。
2. **患者移动端 (Mobile H5)**
   - **HJ自助签到终端**（目录 `HJ自助签到终端`）：患者现场扫码签到（Nginx 路径建议 `/checkin`）。
   - `HJ体检H5`：体检项目动态路径规划导检（Nginx 路径建议 `/checkup`）。
3. **大屏与门边屏 (Displays)**
   - **HJ候诊区大屏**（目录 `HJ候诊区大屏`，Vue3 + Vite）：候诊区综合屏 (`/GlobalHub`)、叫号模板 (`/pdjh1` 等)；Nginx `/screen`。诊室门边屏请用独立项目。
   - **HJ诊室门边屏终端**（目录 `HJ诊室门边屏终端`）：诊室门口 9:16 竖屏；Nginx `/clinic`。
4. **管理后台与医生控制台 (Workstations)**
   - **HJ管理后台**（目录 `HJ管理后台/Gocent.Manager`）：Web 管理控制台（字典、排班、规则配置）；构建 `publicPath` 为 `/PDJHManagement`，Nginx 可映射为 `/admin` 或保持 `/PDJHManagement`。
   - **HJ叫号器**（目录 `HJ叫号器`）：WPF 通用叫号器（Windows 安装包分发）。
5. **官网 (可选)**
   - `HJ官网`：静态展示页，Nginx 根路径 `/`。

## 二、 第一阶段：IT 基础设施准备 (Infrastructure)

建议在医院内网中心机房（或医疗专属云）准备至少 2 台高可用服务器节点。

- **节点 A（应用服务器）**：推荐 4核 CPU / 8G 内存，OS: CentOS 7.x+ 或 Ubuntu 20.04+。
- **节点 B（数据与中间件服务器）**：推荐 8核 CPU / 16G 内存，OS: CentOS 7.x+ 或 Ubuntu 20.04+。

### 1. 基础数据源与应用运行环境配置

为保障全院早高峰时段的高并发业务稳定运行，请完成以下基础中间件服务的安装与调优：

**节点 B（数据中心）服务组件：**

- **MySQL 8.0+**：创建名为 `pdjh` 的数据库，并导入初始化表结构脚本。需配置 `lower_case_table_names=1` 防范系统变量大小写敏感问题，字符集统一使用 `utf8mb4`。
- **Redis (单点/哨兵/集群模式)**：基于 Redisson 构建分布式锁机制，确保在多科室、高并发接诊操作下的数据强一致性，有效隔离并发操作引发的脏读或业务冲突现象。挂号与入队请求由 `pdjh-server` 同步落库处理；若 HIS 批量推送峰值较高，可在应用层通过限流、连接池与数据库索引优化承载，无需单独部署消息中间件。

**节点 A（应用中心）服务组件：**

- **JDK 17**：核心后端引擎的必要 Java 运行环境。
- **Nginx**：作为系统所有前端静态资源的 Web 容器，以及各类 API 与 WebSocket 长连接请求的反向代理代理服务器。
- **Node.js 16+** (限编译/构建机)：用于将 Vue 前端工程进行本地构建与编译生成静态资源。

## 三、 第二阶段：后端微服务集群部署

### 1. 服务编译与打包

在开发环境或 CI/CD 流水线中执行构建指令：

```bash
cd pdjh-server
mvn clean package -DskipTests
```

将构建输出的 `target/pdjh-server-0.0.1-SNAPSHOT.jar` 部署至应用节点 A 的 `/opt/huanjiang/server/` 目录。

### 2. 启动核心服务

为确保服务的高可用性，建议使用 `Systemd` 或 `Supervisor` 托管 Java 进程持续运行。以基础免托管方式为例，可通过以下命令启动：

```bash
nohup java -Xms2g -Xmx4g -jar pdjh-server-0.0.1-SNAPSHOT.jar --spring.profiles.active=prod > server.log 2>&1 &
```

**安全部署规范（DevSecOps 约定）：** 
出于等保与信息安全合规要求，数据库密码等敏感凭证严禁硬编码于 `application.yml` 中。启动服务前，必须由系统层注入环境变量（例如 `export DB_PASSWORD=your_password`）。同时，基于安全隔离策略，系统的 Prometheus 指标监控端口已独立映射至 `9091`，应限制为仅内网特定网段可访问。

## 四、 第三阶段：前端矩阵发布与硬件终端接入

基于“一次编译，终端自适应路由”的设计理念，首先在构建机对所有 Vue 前端服务执行 `npm run build` 生成静态资源，随后按照以下网络拓扑部署配置。

### 1. Nginx 反向代理与静态资源配置

在应用节点 A 编辑 Nginx 配置文件。假设后端 API 服务运行于本机或局域网内的 `192.168.1.100:8080`：

```nginx
server {
    listen 80;
    server_name queue.hospital.local; # 院内 DNS 映射

    # 1. 候诊区大屏 (Vue3)
    location /screen/ {
        alias /usr/share/nginx/html/screen/;
        try_files $uri $uri/ /screen/index.html;
    }

    # 1b. 诊室门边屏
    location /clinic/ {
        alias /usr/share/nginx/html/clinic/;
        try_files $uri $uri/ /clinic/index.html;
    }

    # 2. 患者签到
    location /checkin/ {
        alias /usr/share/nginx/html/checkin/;
        try_files $uri $uri/ /checkin/index.html;
    }

    # 3. 运营控制台
    location /admin/ {
        alias /usr/share/nginx/html/admin/;
        try_files $uri $uri/ /admin/index.html;
    }

    # 反向代理与 WebSocket
    location /api/ {
        proxy_pass http://192.168.1.100:8081/api/;
        proxy_set_header Host $host;
        
        # 维持 StompJS/SockJS 全双工长连接机制
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_read_timeout 3600s;
        proxy_send_timeout 3600s;
    }
}
```

### 2. 硬件铺设与终端配置指导（安卓 WebView 双线绑定）

推荐现场使用 **安卓 WebView Kiosk Shell**（规范见 [android-shell-spec.md](../android/android-shell-spec.md)），三端首页分别为 `/screen/`、`/clinic/`、`/checkin/`。

**绑定方式（二选一）：**

1. **路径 A（自助登记）：** Shell 注入 `getDeviceId()` → H5 调用 `Terminal/Register` 创建待配置记录 → 管理后台「屏幕管理 / 签到终端管理」补全诊室绑定并启用。
2. **路径 B（预配置）：** 管理后台先创建 deviceCode → 终端 H5「录入设备编号」→ `Terminal/Resolve` 通过后进入业务页。

基于 Monorepo 构建，候诊大屏与门边屏可一键打包：

```powershell
# 仓库根目录
npm run build:displays      # 候诊大屏 + 门边屏
npm run build:terminals     # 上述 + 自助签到
npm run build:admin         # 管理后台
npm run build:frontends     # 全部患者终端 + 后台

# 或 Windows 脚本
.\scripts\build-terminals.ps1
.\scripts\build-all-frontends.ps1
```

现场升级步骤详见 [显示屏终端升级检查清单](./显示屏终端升级检查清单.md)。

单独构建：

```bash
cd HJ候诊区大屏 && npm install && npm run build   # -> dist/ 部署 /screen
cd HJ诊室门边屏终端 && npm install && npm run build # -> dist/ 部署 /clinic
```

- **候诊区大屏 Shell：** `terminalType=SCREEN`，就绪后按后台 `templateRoute` 跳转（如 `/pdjh4`、`/GlobalHub`）。
- **诊室门边屏 Shell：** `terminalType=CLINIC`，绑定 1 个物理诊室；显示配置见后台「门边屏显示配置」。
- **自助签到 Shell：** `terminalType=CHECKIN`，绑定诊区诊室后开放签到。
- **叫号器（Windows）：** 将预编译叫号器安装包下发至门诊/药房/检验/体检窗口终端，悬浮窗可嵌入 HIS。

## 五、 第四阶段：初始化与试运行验收 (UAT)

在包含服务器、网络及硬件通信组件节点部署联通之后，项目实施组需分批覆盖执行以下 5 项实景压测与上线 UAT 验收流程：

1. **强规则依赖与路由算法验证**
   在 **HJ管理后台** 规则配置中心配置并启用「B 超」项目强依赖「抽血」完成的业务规则。通过 `HJ体检H5` 模拟患者全流程签到，验证系统是否优先指向采血窗口，并且在 LIS 回传完结信号前，严格拒绝将其编入 B 超候诊队列。
2. **违约降级与过号惩罚机制测试**
   注入一条超时过期的预约测试数据，使用 **HJ自助签到终端** 进行场内扫码迟到报到，确认 `isAppointment` 优先级降级及过号惩罚策略生效。
3. **高可用自动负载与熔断演练**
   模拟某检查室不可用，由分诊护士在护士站执行 **科室熔断/暂停 (Suspend Dept)**，验证等候池重路由与大屏换线指引。
4. **边缘网关 (Edge Agent) 离线同步探测**
   在物理隔离场景部署 Edge Agent，验证加密 Webhook 长连接数据同步（详见 [医院接口对接实施方案](../integration/医院接口对接实施方案说明.md)）。
5. **管理驾驶舱 SLA 效能验收**
   登录 **HJ候诊区大屏** 效能看板（`/#/directorDashboard`），验证 SLA 超时告警与科室负荷统计。

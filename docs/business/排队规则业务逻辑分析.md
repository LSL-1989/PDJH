## 一、核心洞察：四条业务线，四种本质不同的调度模型

> **"排队叫号"这个词，掩盖了四条业务线之间截然不同的调度本质。**
> 用同一套配置范式管理四条业务线，是当前系统配置中心最大的设计错误。

| 维度 | 门诊就诊 | 药房发药 | **门诊医技检查** | 体检导检 |
|------|---------|---------|----------------|---------|
| **调度模型** | 线性单队列 | 池化分配 | **并联独立队列** | 图路径规划 |
| **服务站点** | 1个（固定诊室） | 1个（任意窗口） | **每科1个独立队列** | N个（全部科室） |
| **患者路径** | 等→进→出（一次） | 等→取（一次） | **多条路径并行，各自独立** | 系统自动串联N站 |
| **谁决定下一站** | 医生诊室固定 | 系统分窗算法 | **患者自己决定顺序** | 系统实时算路决定 |
| **路径控制权** | 系统管控 | 系统分配 | **患者自主** | 系统主导 |
| **核心约束** | 顺序/优先级 | 超时/窗口容量 | **报告时效/结果依赖** | 依赖关系/空腹/动态队列 |
| **配置复杂度** | ⭐⭐ | ⭐⭐⭐ | ⭐⭐⭐ | ⭐⭐⭐⭐⭐ |

## 二、门诊就诊排队 — 线性单队列模型

### 2.1 业务场景

患者挂号取号，进入指定科室/医生的排队队列，按先后顺序叫号进入诊室就诊。
患者路径：**取号 → 等候 → 叫号 → 就诊 → 结束**（一次性完成）

### 2.2 核心状态机

```
取号
 │
 ▼
[等候中] ─────── 到号叫出 ──→ [被叫到] ──→ [就诊中] ──→ [就诊完成]
    │                              │
    │                              └── 超时无应答 ──→ [过号]
    │                                                    │
    │                              ┌─────────────────────┘
    │                              ▼
    │                           重排末位（过号次数 < maxSkipCount）
    │                              OR
    │                           彻底过号作废（过号次数 ≥ maxSkipCount）
    │
    └── 患者主动离开 ──→ [取消]
```

### 2.3 规则配置的真实需求（顺序公平性调节）

| 规则类别 | 业务问题 | 配置项 | 配置形式 |
|---------|---------|-------|---------|
| **叫号超时** | 叫到号多久没来算"过号"？ | `callTimeoutMin` | 数字（分钟） |
| **过号惩罚** | 过几次才彻底踢出队列？ | `maxSkipCount` | 数字（次） |
| **复诊优先** | 当天已就诊患者二次复进的排队权重 | `revisitWeight` | 权重数字（0-100） |
| **特殊人群优先** | 老年人/残障/孕妇是否置顶？ | `elderPriority` | 开关 |
| **急诊插队** | 急诊患者是否可以无限制插入队首？ | `emergencyInsert` | 开关 |
| **准备预呼叫** | 提前叫几个人站起来准备？ | `preCallCount` | 数字（人） |
| **微信/短信提醒** | 到第几位时推送排队提醒给患者？ | `smsAdvanceCount` | 数字（人） |

### 2.4 配置方式建议

> ✅ **适合独立参数表单**：每个参数一个控件，简单直接，护士长和门诊主任均可操作。
> ❌ **不适合 JSON 编辑器**：运营人员不理解 JSON 结构，容易配错。

## 三、药房发药排队 — 池化分配模型

### 3.1 业务本质：处方分窗，而非患者分窗

| 对比维度 | 门诊就诊 | 药房发药 |
|---------|---------|---------|
| 分配对象 | 患者 → 固定医生 | 处方 → 任意合适窗口 |
| 等候原因 | 医生逐一看诊（串行） | 药师忙于备药（并发） |
| 超时后果 | 患者不来，诊室空转 | 患者不来，已备药物滞留浪费 |
| 关键指标 | 过号率 | **取药等待时长 + 窗口积压量** |

### 3.2 核心状态机

```
医生开具处方
     │
     ▼
  患者缴费完成
     │
     ▼
  药房取号（可自助机/护士站）
     │
     ▼
[等候池]  ←── 系统定时扫：等候 > 30min → 超时作废告警
     │
     ▼ 系统按算法分配窗口（最短队列/轮询/按类型）
     │
[指定窗口备药中]
     │
     ▼
  叫号（"X号请到X窗口取药"）
     │
     ▼
[患者取药]
     │
     ├── 正常取走 ──→ [完成]
     │
     └── 超时无人取 ──→ [滞留告警] ──→ 人工处理
```

> 📌 **关键区别**：药房的"超时"发生在**备药完成后**患者迟迟不来取，而不是叫号无人应答。
> 这意味着超时告警的处理对象是"药"（已取到窗口的处方药），而不是"队列位置"。

### 3.3 规则配置的真实需求

| 规则类别 | 业务问题 | 配置项 | 配置形式 |
|---------|---------|-------|---------|
| **等候超时** | 等候池中超多久自动告警/作废？| `timeoutMinutes` | 数字（直接驱动后端定时任务！） |
| **窗口分流算法** | 如何把处方分配到窗口？ | `splitAlgorithm` | 枚举选项：最短队列 / 轮询 / 按药品类型 |
| **专用窗口** | 急诊药/中草药是否要专窗独立处理？ | `emergencyWindowEnabled`, `separateChinaWestern` | 开关 |
| **窗口积压阈值** | 单窗口积压多少单时触发告警？ | `maxPendingPerWindow` | 数字 |
| **催取药提醒** | 备好药后多久推送"请来取药"提醒？ | `firstReminderMin`, `repeatReminderMin` | 数字（分钟） |

### 3.4 配置方式建议

> ✅ **运营参数**（超时/阈值）→ 数字输入框，药房主任可配置
> ✅ **分流策略**（窗口算法）→ 卡片式枚举选择，配合文字说明让主任理解各算法含义和适用场景

## 四、【关键遗漏】门诊医技检查排队 — 并联独立队列模型

### 4.1 业务场景描述（最易与体检混淆）

门诊患者在医生就诊后，被开具化验单或检查单，需要去医技科室做以下各类检查：

| 医技类型 | 典型科室 | 患者来源 |
|---------|---------|---------|
| **抽血/化验** | 检验科（LIS）| 医生开具血常规、生化、尿检等检验单 |
| **超声检查** | 超声科 | 医生开具B超/彩超单（腹部、心脏、甲状腺等） |
| **影像检查** | 放射科（PACS）| 医生开具胸片/CT单 |
| **心电检查** | 心功能室 | 医生开具心电图/动态心电单 |
| **其他** | 内镜室/病理科等 | 各类专科检查 |

### 4.2 ⚡ 与体检导检的根本区别（最重要）

```
┌─────────────────────────────────────────────────────────────────┐
│          门诊医技检查 vs 体检导检：本质上是两个完全不同的系统       │
├──────────────────────────┬──────────────────────────────────────┤
│      门诊医技检查          │           体检导检                     │
├──────────────────────────┼──────────────────────────────────────┤
│ 患者自行决定去哪个科室      │ 系统自动计算并告知患者去哪个科室       │
│ 每个科室是独立的排队队列    │ 系统串联所有科室，统筹调度            │
│ 患者可能只做其中1-2项      │ 患者必须完成套餐内所有项目            │
│ 各科室之间没有系统联动      │ 某项完成后系统立即派发下一项         │
│ 来源：医生处方单           │ 来源：预约/登记的体检套餐            │
│ 无路径规划（患者自行安排）  │ 系统主动规划最优路径                │
│ 结果可能当天不出（CT/病理）│ 体检报告统一在体检中心出具          │
└──────────────────────────┴──────────────────────────────────────┘
```

> ⚠️ **产品关键判断**：门诊医技检查中，**系统不能也不应该**替患者决定检查顺序，
> 因为不同检查的结果出具时间不同，患者的行程安排各异，且部分检查有特殊前置要求
>（CT需要提前喝造影剂、胃镜需要预约时间段等）。

### 4.3 门诊医技叫号的核心逻辑

```
医生就诊完毕，开具检查/化验单
         │
         ▼ （HIS系统收费完成后，叫号系统收到通知）
         │
    ┌────┼────────────────────────────────────────┐
    │    │   各科室独立运作，互不知晓对方队列状态   │
    │    │                                        │
    ▼    ▼                      ▼                 ▼
[检验科]              [超声科]            [放射科(CT)]      [心电图室]
 独立队列               独立队列            独立队列          独立队列
 自助/护士取号           自助/护士取号        预约制+叫号        自助取号
    │                    │                   │                 │
    ▼                    ▼                   ▼                 ▼
 [等候区]             [等候区]             [等候区]          [等候区]
    │                    │                   │                 │
    ▼                    ▼                   ▼                 ▼
 叫号窗口              叫号诊间            叫号检查室         叫号检查室
    │                    │                   │                 │
    ▼                    ▼                   ▼                 ▼
 [出具报告]           [出具报告]           [出具报告]         [出具报告]
    │                    │                   │                 │
    └────────────────────┴───────────────────┴─────────────────┘
                                 │
                                 ▼
                   患者凭全部报告回诊室复诊（或当天直接看报告）
```

### 4.4 各医技科室的子类差异

不同医技科室的叫号逻辑有**显著差异**，不能一刀切：

#### A. 检验科（抽血）— 窗口批量服务模型

```
特点：
  - 多个采血窗口并联，单次服务时间短（3-5分钟/人）
  - 患者量大，峰值明显（早8-10点为抽血高峰）
  - 需要空腹的项目有时间窗口限制（不超过上午11点）

叫号逻辑：
  取号（自助机/叫号机）
     │
     ▼
  [候检区等候]
     │  按号码顺序叫号
     ▼
  "XX号请到X窗口采血"  ← 系统自动分配最空闲的采血窗口
     │
     ▼
  采血完成 → 标本送检验室处理
     │  2-4小时后出报告（LIS系统）
     ▼
  患者可离开等待报告（不需要在场等待）

关键配置需求：
  ① 窗口数量及各窗口的开放状态（动态配置）
  ② 空腹项目的等候区优先叫号规则（早高峰期）
  ③ 急诊标本的优先叫号（急诊采血优先于普通门诊）
  ④ 一人多管合并叫号（同一患者多个检验项目一次采血）
```

#### B. 超声科（B超/彩超）— 时段预约+当日叫号混合模型

```
特点：
  - 检查时间较长（10-30分钟/人）
  - 不同超声类型需要不同的准备（空腹/充盈膀胱/无需准备）
  - 有多个检查室（探头类型不同）
  - 高峰期排队时间可长达2-3小时

叫号逻辑（两种模式）：
  模式A - 纯当日排队：
    取号 → 候检区等候 → 叫号进检查室 → 出报告

  模式B - 预约+当日混合（推荐，解决长时间等待）：
    预约患者（提前1-7天预约时段）→ 分时段叫号
    当日取号患者     → 与预约患者混合排队，预约患者权重更高

关键配置需求：
  ① 是否启用预约模式（开关）
  ② 预约患者 vs 当日患者的权重比（如预约优先级7，当日优先级3）
  ③ 不同超声类型分检查室叫号（腹部超声/心脏超声/血管超声分开叫）
  ④ 空腹患者早上优先叫号规则
  ⑤ 单次检查预估时长配置（影响大屏显示等候时间预估）
```

#### C. 放射科（CT/胸片）— 预约制+分设备叫号模型

```
特点：
  - CT检查时间长，设备价格昂贵，必须精细预约
  - 部分检查需注射造影剂（有过敏反应观察等待期）
  - 胸片快（5分钟），CT慢（15-30分钟，不含报告）
  - 报告出具时间长（CT报告1-2小时，病理可能数天）

叫号逻辑：
  胸片（X光）：类似门诊排队，快进快出，当日取号 → 叫号 → 出报告（30分钟内）

  CT/MRI：
    必须预约时间段（系统限制单时段人数）
       │
       ▼
    患者按预约时间到达
       │
       ▼  核对预约信息/费用
       ▼
    [等候区] 按预约时间精确叫号（而不是取号顺序）
       │
       ▼
    进入CT室扫描（部分需要口服造影剂等待30-60分钟）
       │
       ▼
    扫描完成 → 等候报告（1-2小时，患者可离开）

关键配置需求：
  ① 是否全预约制（CT必须，胸片可选）
  ② 单时段预约配额（如每15分钟放2个CT号）
  ③ 设备分线叫号（CT1/CT2/MRI分别独立叫号）
  ④ 造影剂等待期的专属等候区叫号
  ⑤ 危急值报告的加急叫号（紧急通知患者）
```

#### D. 心电图室 — 快速窗口叫号模型

```
特点：
  - 检查时间极短（5-8分钟/人）
  - 无特殊前置要求（无需空腹/特殊准备）
  - 患者量大，设备多台可同时运行
  - 报告当场出具（实时）

叫号逻辑（最接近门诊排队，但有多设备并联）：
  取号（自助机）
     │
     ▼
  候检区等候
     │  按号顺序叫，系统自动分配最空闲的心电检查床
     ▼
  "XX号请进X号检查室"
     │
     ▼
  检查完成（5分钟）→ 报告当场出具
     │
     ▼
  患者离开（凭单复诊或当场看报告）

关键配置需求：
  ① 检查床/设备数量（影响系统并联叫号上限）
  ② 普通心电 vs 动态心电（Holter）分流（Holter需要佩戴24小时设备，流程完全不同）
  ③ 急诊心电图优先跳队规则（急性胸痛需要10分钟内完成心电）
```

### 4.5 门诊医技检查整体状态图（患者视角）

```
门诊医生就诊
     │
     ▼ 医生开具检查/化验单
     │
     ▼ 患者缴费（线上/窗口/自助机）
     │
     ├─────────────────────────────────────────────────────────┐
     │                                                         │
     ▼                                                         ▼
[患者自主决定先去哪个科室]              系统在各科室独立推送：
     │                                 "您有1项检查待做（超声科）"
     │                                 "您有1项化验待做（检验科）"
     ▼                                 等候时间预估、大屏展示
  各科室独立排队叫号
  （见4.4节各科室子流程）
     │
     ▼
[完成所有检查]（可能需要1-3小时，跨越多个科室）
     │
     ▼
[等待报告出具]（时长不一：血检2-4h / 彩超即时 / CT 1-2h）
     │
     ▼
患者复诊（带报告回门诊医生处）
  OR
患者直接在网上/自助机查看报告
```

### 4.6 门诊医技检查的关键规则配置需求

与门诊就诊不同，门诊医技的规则配置有**跨科室统筹**和**科室个性化**两个维度：

#### 跨科室统筹配置（全院统一）

| 规则类别 | 业务问题 | 配置项 | 配置形式 |
|---------|---------|-------|---------|
| **急诊优先规则** | 急诊患者在所有医技科室的优先级如何？ | `emergencyPriorityLevel` | 枚举（插队首位/权重加成/专用通道） |
| **缴费完成联动** | 缴费完成后多久自动为患者开通各科室取号权限？ | `paymentSyncDelay` | 数字（秒，决定与HIS同步延迟） |
| **报告结果通知** | 报告出具后是否通过微信/短信通知患者？ | `reportNotifyEnabled` | 开关 |
| **多科室消息聚合** | 当患者有3个科室要做时，如何推送提醒不骚扰？ | `multiDeptMsgStrategy` | 枚举（合并推送/分开推送） |

#### 科室个性化配置（各科室独立）

| 规则类别 | 检验科 | 超声科 | 放射科 | 心电图室 |
|---------|--------|-------|-------|---------|
| **取号方式** | 自助取号 | 自助取号/预约 | 预约制 | 自助取号 |
| **服务模式** | 多窗口分流 | 多检查室分流 | 分设备分流 | 多检查床分流 |
| **空腹优先** | ✅ 需要 | ✅ 部分需要 | ❌ 不需要 | ❌ 不需要 |
| **急诊插队** | ✅ 需要 | ✅ 需要 | ✅ 需要 | ✅ 最紧急 |
| **预约模式** | ❌ 不需要 | ✅ 建议开启 | ✅ 必须 | ❌ 不需要 |
| **报告实时性** | 2-4小时 | 即时 | 1-2小时 | 即时 |

### 4.7 门诊医技 vs 体检导检：配置入口对比

```
门诊医技检查（各自独立）          体检导检（系统统筹）
┌────────────────────┐          ┌─────────────────────────┐
```

## 五、体检导检排队 — 图路径规划模型（最高复杂度）

### 5.1 业务场景与核心挑战

体检患者需要依次完成多个科室的检查项目（血液、彩超、心电图、眼科……），各项目间存在**依赖关系**，且每个科室实时排队人数不同。系统需要主动替患者规划最优路径。

体检中心核心运营挑战：

> **如何让多位同时在场的体检者，互不拥堵，总体完成时间最短？**

### 5.2 与门诊医技的根本区别

```
门诊医技：患者持检查单自行前往各科室 → 各科室独立叫号 → 患者自行安排顺序
          「拉式」：患者主动拉取服务

体检导检：系统持续跟踪患者状态，主动派发下一站指令 → 患者按系统提示行动
          「推式」：系统主动推送导航
```

### 5.3 当前实现算法（基于 ExamRoutingService.java）

通过 `RULE_EXAM.triageAlgorithm` 配置切换：

| 算法名 | 实现逻辑 | 适用场景 |
|--------|---------|---------|
| `FASTING_FIRST` | 优先选择需要空腹的项目 | 默认策略，早上患者签到时 |
| `LEAST_WAIT` | 选当前排队人数最少的科室 | 高峰期均衡各科室负载 |
| `SHORTEST_PATH` | 当前等效 LEAST_WAIT（待完整实现，加地理距离） | 未来扩展 |
| `NONE` | 不自动派单，等待人工干预 | 系统异常降级 |

### 5.4 体检路由决策树

```
患者所有待检项目（state = 0 = 待检）
        │
        ▼ 硬性过滤1
① 剔除「关联科室已挂起」的项目（设备故障则绕开）
        │
        ▼ 硬性过滤2
② 剔除「前置依赖未完成」的项目
   （腹部彩超 dependsOn 血常规 → 血常规未完成则跳过彩超）
        │
        ▼ 软性排序（按 RULE_EXAM 算法）
③ 在可做项目中选最优下一站
        │
        ▼
④ QueueService.enqueue() → 推入目标科室排队
⑤ 标记该项目 state = 1（已派单）
        │
        ▼ 等待触发
患者完成此项 → ExamItemCompletedEvent → 重复①
```

### 5.5 体检规则配置的四层体系

```
层次1 基础层 — 检查项目字典（dict_exam_item 表）
  ├─ 项目名称、关联科室、是否空腹、性别限制、平均耗时
  └─ 前置依赖关系（dependsOnIds）← ⚠️ 当前是字符串，需可视化

层次2 套餐层 — 体检套餐（exam_package 表，待建）
  ├─ 套餐名称、适用人群、价格
  └─ 包含哪些检查项（多对多）← ⚠️ 当前无套餐-项目 UI 管理

层次3 策略层 — 算路算法（RULE_EXAM 在 SysConfig）
  └─ 算法选择 + 分时生效策略 ← ⚠️ 当前只能在规则中心改 JSON，应在主任工作台快捷切换

层次4 干预层 — 实时运营干预（操作面板，非配置入口）
  ├─ 科室挂起重路由（suspendDept）
  ├─ 护士强制指定下一站（forceRoute）
  └─ 手动重新算路（recalculateRoute）
```

### 6.2 配置范式建议

|--------|---------|---------|------------|
| **门诊就诊** | 公平性参数 | 独立参数表单（数字+开关） | 规则配置中心 → 门诊 |
| **药房发药** | 分窗算法选择 | 算法卡片 + 参数表单 | 规则配置中心 → 药房 |
| **门诊医技** | 各科室独立参数 | **按科室分标签页的参数表单** | 规则配置中心 → 医技 → [检验/超声/放射/心电] |
| **体检导检** | 算路策略选择 | **策略卡片（主任工作台）** + 字典/套餐管理 | 主任工作台（策略切换）+ 体检套餐管理（字典/套餐） |

### 6.3 各科室在四条业务线中的身份对比

| 科室 | 门诊就诊 | 门诊医技 | 体检导检 |
|------|---------|---------|---------|
| **检验科/采血室** | 不涉及 | 独立叫号（自助取号/多窗口） | 体检路由中的一个节点 |
| **超声科** | 不涉及 | 独立叫号（预约制/混合制） | 体检路由中的一个节点 |
| **放射科(CT)** | 不涉及 | 预约制叫号（时段分配） | 体检路由中的一个节点 |
| **心电图室** | 不涉及 | 独立叫号（多检查床并联） | 体检路由中的一个节点 |
| **门诊诊室** | ✅ 核心场景 | 不涉及 | 不涉及 |
| **药房** | 不涉及 | 不涉及（独立场景） | 不涉及 |

> 📌 **关键洞察**：同一个检验科，在门诊医技场景下是"被动接受各路患者自行来取号"，
> 在体检导检场景下是"被系统主动推送患者过来排队"。
> **两套逻辑并存于同一科室**，必须在系统层面明确区分两类患者的来源和优先级。

## 七、当前系统的关键设计缺口

### 7.1 门诊医技检查缺失的核心功能

| 优先级 | 缺失功能 | 说明 | 影响 |
|--------|---------|------|------|

| 🔴 P0 | **缴费完成 → 自动开放取号权限** | 当前患者缴费后需手动或扫码才能取号，应与HIS缴费状态联动 | 患者体验差，取号环节多 |
| 🟠 P1 | **超声科/CT预约模式** | 高峰期等待超过2小时，预约制是必须的解决方案 | 患者体验差，易流失 |

| 🟠 P1 | **急诊10分钟心电绿色通道** | 急性胸痛患者的心电图必须在10分钟内完成，需要全时段最高优先级 | 医疗安全问题 |
| 🟡 P2 | **门诊医技等候时间预估** | 患者取号后看到"预计等候X分钟"，减少焦虑 | 患者满意度 |

## 一、 产品定位与愿景

欢匠·序流排队分诊管理系统主要致力于解决医疗机构中患者就诊流程不清晰、等候时间长及现场秩序混乱等痛点。本系统作为医疗机构门诊和医技科室的“智慧交通调度枢纽”，旨在将无序的患者流动转化为基于业务规则、智能调度算法与 SLA 标准体系的有序数字工作流，从而全面提升患者的就诊体验和医院的运营效率。

## 二、 核心业务流转与用户赋能

系统通过三个核心终端实现医院候诊场景的闭环体验，全面服务于三大类用户群体：

1. **患者与家属（C端体验层）**：核心诉求为“明指引、少等待”。通过移动端导诊与实时排队进度雷达，为患者提供清晰的就医路线与时间预期。
2. **医生与护士（B端操作层）**：核心诉求为“简操作、强管控”。提供极简化的桌面端医护工作站，支持顺呼、重呼及急危重症患者的一键优先调度。
3. **医院管理者（M端决策层）**：核心诉求为“保秩序、优效能”。通过院级管理驾驶舱提供的排队热力图与 SLA 监控，动态评估科室接诊负荷，赋能排班调整与潮汐分流。

## 三、 全场景核心组件与功能优势

### 终端矩阵（项目名称）

| 项目名称 | 仓库目录 | 主要用户 |
|---------|---------|---------|
| **HJ自助签到终端** | `HJ自助签到终端` | 患者现场签到 |
| **HJ叫号器** | `HJ叫号器` | 门诊/药房/检验/体检窗口叫号 |
| **HJ候诊区大屏** | `HJ候诊区大屏` | 候诊区公众与语音叫号 |
| **HJ诊室门边屏终端** | `HJ诊室门边屏终端` | 诊室门口信息展示（可选部署） |

### 1. 患者移动端：就医向导与流程减负 (SaaS H5 / 微信生态)
为患者提供轻量级交互体验，扫码即用、即用即走，深度融合医院现有微信生态。

<!-- 产品截图可放置于 docs/assets/ 并在此引用 -->

* **精准防伪签到拦截**：患者通过医院官方公众号入口进行签到，系统将自动校验 HIS 系统的预约时段信息。对于未到预约时段的患者实施签到拦截，有效避免院区内人群无效滞留。
* **智能导诊路由算法 (Smart Routing Radar)**：首创算法驱动的动态导诊引擎。在并行检查项目（如多项开单体检）场景下，系统基于“禁食禁水约束条件”及“各区域实时拥堵指数”，为患者动态规划最优就医路径。

### 2. 调度执行终端：极简操作与业务管控（HJ叫号器）
为医务工作者降低软件操作负担，无缝嵌入现有工作流。

* **免侵入式悬浮窗设计**：基于 WPF 桌面端，提供置顶悬浮组件。顺呼、重呼、过号、完成等高频动作均可一键触发，不干扰 HIS、PACS、LIS 等核心业务系统的正常使用。门诊、药房、检验、体检窗口共用同一套叫号器。
* **灵活动态的规则调度引擎 (Triage Engine)**：高度适配大型三甲医院的复杂排队规则：
  * 支持强制二次扫码验证，杜绝患者未到场导致的“空号”现象。
  * 引入防呆防误机制，多次空呼过号系统将自动执行延迟或丢弃策略。
  * 针对复诊、检验结果回传等业务场景提供高优先级算法排班。
* **人工干预与应急通道特权 (Force Route)**：系统提供高级干预权限。面对突发情况（如急危重症、特殊优抚对象等），导诊台护士可使用强制定向分派（Manual Cut-In）、平移转诊队列（Force Swap）、以及过号恢复（Revive）等功能，确保应急秩序。

### 3. 全局可视大屏矩阵：候诊区秩序护航者
系统内置基于响应式架构的 Web 终端显示应用，通过统一的配置和终端识别即可在各类物理终端上无缝呈现。

* **业务驱动的多模态展示**：
  * **候诊区综合屏**：呈现当前候诊大区所有开诊医生的状态列表，并整合独立的智能 TTS 语音服务，实现无缝平滑的语音合成播报（如：“请 A005 号张三到 1 诊室就诊”）。
  * **门头诊边屏**：专注负责单一诊室的门禁与信息展示。系统底层严格遵循安全脱敏规范，实行基于 Spring Security 的零信任连接管控制度，实现患者姓名的隐私脱敏展示（如 `张*三`），有效阻断非法数据监听。

### 4. 院长效能看板中枢：数据驱动的管理沙盘
打造以历史趋势和实时侦测为核心的数据决策中枢。

* **SLA 监控与全链路预警体系**：为各科室设定基准等候时长（SLA），实时监控候诊时长水位线。在面临排队拥堵及超时警告时，后台控制中心提供可视化预警与源头追溯分析。
* **物理节点资源热力图分析 (Heatmap)**：依托高维数据面板，多维度记录全院排队节点的饱和度，为波峰削谷和排班资源的灵活调配提供量化数据支撑。
* **全局业务规则配置中心**：统一定义并下发医院排队业务底盘配置，支持跨科室字典管理、排队节点生理依赖约束关系配置及过号处理步长等复杂逻辑设定。

## 四、 核心技术底座与异构兼容方案 (Tech Highlights)

1. **面向高并发与大规模下沉的纯血架构设计**：
   摒弃繁杂的基础设施依赖，系统基于纯粹的关系型数据库方案（MySQL）与 Java 并发锁（Concurrent Level & 行级锁）模型，可轻松承载十万级排队流量与毫秒级终端响应。精简的部署模型（仅需 JDK + MySQL + Nginx）极大降低了地市级及基层医疗机构的机房运维成本与实施门槛。

2. **高可用多协议异构网关系统 (Integration SPI Gateway)**：
   针对复杂异构医疗信息系统环境，内置四大自适应通讯协议与探针技术：
   * **标准网关**：采用 `HTTP / Webhook / WebService` 协议实现与现代 HIS 的实时挂号事件联动。
   * **非侵入式探针**：提供基于 `JDBC Polling` 的旁路数据抓取探针，无需接口级开发即可通过定时构建视图或表同步机制实现单向对接。
   * **边缘隔离探针 (Edge Agent)**：专门针对对内网隔离有极高要求的特殊院区，提供轻量级边缘探针组件。单向对外网建立受控长连接通信，实现物理逻辑级安全隔离的数据同步。

3. **敏捷工程与实施工作台 (Implementation Tech Suite)**：
   * **云端标准模板库 (Marketplace)**：固化并沉淀行业主流 HIS 厂商的接入报文树状结构。一键从云端载入标准适配模板，降低现场实施的人工验证成本。
   * **配置版本管理控制 (Git for Configs)**：对所有异构接口的适配修改代码执行自动化快照与版本控制，支持细粒度的秒级配置灾难回滚。
   * **沙箱联调测试套件 (Dry-Run)**：内置沙箱运行环境，实施工程师可直接注入业务报表 Dummy JSON，在系统运行状态下实时测试验证字段映射结果，有效保障实施阶段系统的可用性与稳定性。

## 五、 五大专业医院全流程场景覆盖

1. **🏥 综合门诊分诊**：全维支撑内、外、妇、儿等科室的签到报到、首诊、复诊、呼叫排序与过号重排业务体系。
2. **💊 发药核对与药房服务**：深度整合缴费结算节点，提供处方状态跟踪、药房配药进度展示机制及窗口叫号一体化功能。
3. **🩸 检验采血中心**：贯通采血大厅报到、试管条码扫描、分配调度全流程，通过第三方接口（LIS）联动实现自动确认及完结退队。
4. **☢️ 医技辅助检查**：针对超声、内镜、放射（CT/MRI）等大型紧缺性医疗设备排队特点，量身打造专项调度机制，执行防拥堵流量削峰与分流。
5. **🩺 综合健康管理与体检**：面向健康管理中心的多项目并行排队设计，引入智能路径推算算法，自动基于项目互斥及禁忌症实现体检项目流程最优化保障。
